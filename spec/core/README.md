# spec/core/ — Requirement Index

The platform-neutral core specification. **This is the single source of truth.** Behavior
questions are answered here, never by reading generated client code (see `CLAUDE.md`).

| Document | Covers |
| --- | --- |
| [protocol.md](protocol.md) | WebSocket wire protocol, framing, dedup, store-and-forward, handshake ordering |
| [client-behavior.md](client-behavior.md) | Client state machine, identity, outbox, inbound dedup, reconnect, persistence |
| [cli-contract.md](cli-contract.md) | Invocation, stdin commands, JSON Lines event schemas, comparison rules |

## Conventions

- RFC 2119 keywords (MUST / MUST NOT / SHOULD / SHOULD NOT / MAY) carry their standard
  meaning. Every normative statement has an ID of the form `REQ-<AREA>-NNN`.
- IDs are **stable**: never renumbered, never reused. Numbering within an area may have
  gaps where requirements were consolidated.
- Generated code MUST cite the IDs it implements in comments (`CLAUDE.md` §4).
- **181 requirements across 27 areas** as of `v1`.

#### `REQ-DEDUP` — server deduplication

| ID | Summary |
| --- | --- |
| REQ-DEDUP-001 | Server durably records every accepted id, for the server's lifetime |

| REQ-DEDUP-004 | Keyed on id alone; survives reconnect |
| REQ-DEDUP-005 | Duplicate's `to`/`text` ignored; first accept wins permanently |

#### `REQ-SNF` — store and forward

| ID | Summary |
| --- | --- |
| REQ-SNF-001 | Accept order: store → `ack` sender → attempt delivery |

| REQ-SNF-003 | Otherwise hold in a per-recipient FIFO queue |
| REQ-SNF-005 | **Drop only on `delivered{id}`** — pushing is not deleting; no timeout, no capacity drop, no queue bound |
| REQ-SNF-006 | Re-push all still-held messages on the recipient's next connect |
| REQ-SNF-007 | Push in server-accept order, every time |
| REQ-SNF-008 | `delivered` for unknown/foreign id ignored; idempotent |
| REQ-SNF-009 | **Sending to a never-seen name is allowed and held** |

| REQ-SYNC-011 | Second `hello` → `already_hello`, session unchanged |

#### `REQ-OUTBOX` — outbox

| ID | Summary |
| --- | --- |
| REQ-OUTBOX-001 | Persistent FIFO at `<data-dir>/outbox.json`, order preserved across restarts |
| REQ-OUTBOX-002 | **Durably written before any network attempt** |

| REQ-OUTBOX-004 | **Entry leaves only on `ack` or permanent rejection**; unbounded, no silent drops |
| REQ-OUTBOX-005 | On `ack`: remove → persist → emit `sent`, at most once per id |
| REQ-OUTBOX-006 | `ack` for an unknown id is ignored |
| REQ-OUTBOX-008 | Restored entries are live but emit no `queued` |
| REQ-OUTBOX-009 | Permanent rejection drops the entry and emits **`error` carrying the dropped message's `ref_id`** |
| REQ-OUTBOX-010 | Retryable error keeps the entry; relays `ref_id` when the server sent one |
